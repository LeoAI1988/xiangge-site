# 记忆同步铁律 Skill

## 一、用途

定义 AI 助手三层记忆（L1/L2/L3）的同步规则。让助手知道：
- 什么时候该同步
- 同步什么内容到哪一层
- 什么时候不该同步

## 二、三层记忆定位

| 层 | 定位 | 容量 | 存什么 |
|----|------|------|--------|
| **L1** | 系统 prompt | 极限（≤ 3KB） | 永久事实（偏好/环境/quirks） |
| **L2** | 工作上下文 | 大 | 项目状态/专题笔记 |
| **L3** | 技术文档 | 大 | API 指南/配置/坑手册 |

**判断标准：** "一周后这个信息还准确吗？"
- 是 → L1
- 否但重要 → L2
- 技术参考 → L3

## 三、10 条同步铁律

### 铁律 1：不重复写已存在的

同步前先搜索（recall/查询），已有则 append，不新建。

### 铁律 2：严格按"一周后还准确"判断

- ✅ "用户偏好简洁回复" → L1
- ❌ "今天买了 100 股 X" → L2（不是 L1）
- ❌ "当前 session 的错误" → 不同步

### 铁律 3：配置/API 坑优先查 L3

不在对话里硬编码 API 端点/凭证/坑点。优先查 L3 skill 文件。

### 铁律 4：L2 写入后必须 GET 回验

写入笔记系统后，立即 GET 一次，确认内容正确写入。

### 铁律 5：业务专题建笔记前必搜索 + 选对笔记本

建任何专题笔记前：
1. 先搜索是否已有同类
2. 确认目标笔记本 ID（不建错分类）
3. 已有则 append，不新建

### 铁律 6：L1 超限必须精简

L1 超 3KB 时：
- 删除过期的索引/临时信息
- 不是删除而是精简（保留事实，删除示例）
- 不在无人值守时大规模删减（避免信息丢失）

### 铁律 7：每日唯一 nid

一个工作日一个 L2 笔记 ID，不建多个。同一天的内容 append 到同一篇。

### 铁律 8：不同步什么

- 临时信息（天气/当前错误）
- 任务进度（属 L2 不属 L1）
- 已过期的状态
- 已在 L3 的技术文档（不复制到 L1）

### 铁律 9：同步输出规范

**沉默 = 成功。异常才出声。**

- ✅ 正常：只输出"记忆同步已同步"
- ⚠️ 发现问题（漏写/写错/层级错）：具体说"问题+修复"
- ❌ 禁止：扫了 N 个 session、补了 M 处的自吹自擂清单

### 铁律 10：M2.7（Lite 模型）用于扫描/补写

同步 cron 用 Lite 模型（省 token），不用 Pro 模型。

## 四、同步执行流程

### Step 1：扫描当前 session

识别"重要但还没同步"的内容：
- 用户偏好变化
- 环境事实更新
- 工具 quirks 发现
- 项目状态变更

### Step 2：判断层级

每个候选项问："一周后还准确吗？"
- 是 + 是事实 → L1
- 否但重要 → L2
- 技术参考 → L3

### Step 3：查重

搜索对应层是否已有同类内容：
- 已有 → append 或 update
- 没有 → create

### Step 4：写入

- L1：直接写 memory（注意容量）
- L2：API 写入笔记系统
- L3：写本地 skill 文件

### Step 5：回验

- L1：读回确认
- L2：GET 回验
- L3：读回确认

### Step 6：输出

- 全部成功 → "记忆同步已同步"
- 有异常 → 列出"问题+修复"

## 五、常见踩坑

### 坑 1：业务专题塞错笔记本

**症状：** 把"业务探讨"塞到"量化笔记"笔记本。

**修复：** 建笔记前必查目标笔记本 ID，不靠记忆。

### 坑 2：L1 塞任务进度

**症状：** L1 写"今天买了 X 100 股"，一周后已清仓，L1 失效。

**修复：** 持仓属 L2，不入 L1。L1 只写永久事实。

### 坑 3：同步输出长清单

**症状：** 每次同步都输出"扫了 N 个、补了 M 处、跳了 K 处"。

**修复：** 沉默 = 成功。异常才出声。

### 坑 4：建重复笔记

**症状：** 同一主题建了 3 个笔记。

**修复：** 建前必搜索。已有则 append。

### 坑 5：凌晨跑同步

**症状：** 凌晨 2 点跑同步 cron，消耗 token 但用户在睡觉。

**修复：** 同步 cron 限定在 8:00-23:00 运行。

### 坑 6：L1 写指令而不是事实

**症状：** L1 写"Always respond concisely"（指令），下次被当指令执行。

**修复：** 写声明式事实（"用户偏好简洁回复"），不写指令。

## 六、输出模板

### 正常情况

```
记忆同步已同步
```

### 发现问题

```
记忆同步发现 1 个问题已修复：
- [层] [笔记 ID]：[问题] → [修复]
```

### L1 超限

```
L1 超限预警：当前 X 字符 / 限制 Y 字符
建议精简项：
- [条目 1]：过期，可删
- [条目 2]：重复，可合并
```
