# 股市专业搜索 Skill

## 一、用途

为股市场景提供多源数据采集和交叉验证。**仅限股市场景使用**（股票/基金/ETF/债券/期货/宏观）。

非股市场景（行业研究/技术/学术/中文文章）请用通用搜索 skill。

## 二、数据源（按优先级）

### 主力源

| 源 | 用途 | 接入方式 |
|----|------|---------|
| **腾讯行情 API** | 实时行情（A 股/港股/指数） | `https://qt.gtimg.cn/q=sh600000,sz000001` |
| **天天基金 API** | 基金净值/估值 | 东方财富开放接口 |
| **东财公告 API** | 上市公司公告 | 东方财富公告爬取 |

### 深度搜索源

| 源 | 用途 | 备注 |
|----|------|------|
| **Tavily** | 7 维深度搜索（机构观点/产业链/海外映射） | 主力，需 API key |
| **DuckDuckGo** | 免费兜底 | `-b yandex` 提升中文质量 |

使用 Tavily 时只从 `TAVILY_API_KEY` 环境变量读取凭证。环境未提供 Tavily 时，改用可用的公开搜索源，并明确说明数据源覆盖差异。

## 三、腾讯行情 API 用法

### 实时行情

```python
import urllib.request

# 多个股票用逗号分隔，必须带 sh/sz/hk 前缀
codes = ['sh600000', 'sz000001', 'sh000001']
url = f'https://qt.gtimg.cn/q={",".join(codes)}'
req = urllib.request.Request(url, headers={'User-Agent': 'Mozilla/5.0'})
data = urllib.request.urlopen(req, timeout=15).read().decode('gbk')
```

### 返回字段解析

返回 `~` 分隔的字段串，关键字段位置：

| 位置 | 字段 |
|------|------|
| 1 | 名称 |
| 2 | 代码 |
| 3 | 当前价 |
| 4 | 昨收 |
| 5 | 今开 |
| 6 | 成交量 |
| 32 | 涨跌幅% |
| 33 | 最高 |
| 34 | 最低 |

### 支持的代码前缀

| 前缀 | 市场 |
|------|------|
| sh | 上海 |
| sz | 深圳 |
| hk | 港股 |

## 四、深度搜索方法论

### 7 维搜索框架

针对一个投资主题，从 7 个维度交叉搜索：

| 维度 | Query 模板 |
|------|-----------|
| **产业政策** | "X 行业 政策 利好 2026" |
| **机构观点** | "X 券商 研报 目标价 2026" |
| **产业链** | "X 产业链 上中下游 龙头" |
| **海外映射** | "X 行业 美股/港股 对标" |
| **资金流向** | "X 板块 北向/南向 资金流入" |
| **风险提示** | "X 行业 泡沫 风险 下跌" |
| **反向搜索** | "X 看空/利空/见顶" |

**反向搜索是核心** — 必须主动找看空理由挑战自己的判断。

### 多源交叉验证

任何一个数据点，至少 2 个源确认：

| 数据类型 | 主源 | 验证源 |
|---------|------|--------|
| 实时价格 | 腾讯 API | 雪球/同花顺 |
| 公告事实 | 东财公告 | 公司官网/巨潮 |
| 机构观点 | 券商研报 | 新闻报道 |
| 产业链信息 | 行业研报 | Wikipedia/专业媒体 |

**冲突时以原始源为准**（公司公告 > 新闻转述 > 自媒体）。

## 五、应用场景

### 场景 1：盘前/盘后复盘

```
1. 腾讯 API 拉取所有持仓+候选的实时/收盘价
2. Tavily 搜索当日重要新闻（7 维）
3. 交叉验证关键数据
4. 输出结构化复盘
```

### 场景 2：新标的调研

```
1. 腾讯 API 拉历史行情
2. Tavily 搜索：公司基本面+行业地位+竞争格局
3. 公告 API 拉最新财报/重大事项
4. 反向搜索：看空理由
5. 输出调研报告
```

### 场景 3：产业链链传分析

```
1. 列出产业链上中下游
2. 每个环节选 1-2 个代表标的
3. 腾讯 API 拉实时行情
4. Tavily 搜索产业催化事件
5. 输出链传图（上游→中游→下游）
```

## 六、H5 单页应用特殊处理

部分金融网站（如券商 App H5）返回的是 3-4KB 的 JS 空壳，直接 curl 拿不到内容。

**正确做法：**
1. 使用当前环境可用的浏览器导航工具加载页面
2. 等待 JS 渲染（3-5 秒）
3. 用 `innerText` 提取渲染后的 DOM 文本
4. 不要 curl 后报"读不了"就跳过

## 七、常见坑

| 坑 | 后果 | 规避 |
|----|------|------|
| 只用 1 个源就出报告 | 数据错误 | 至少 2 源交叉 |
| 跳过反向搜索 | 只看利好，踏空风险 | 强制反向搜索 1 条 |
| 用 OCR 代替实时 API | 收盘价误差 0.21 元 | 以 API 为准 |
| 腾讯 API 不带前缀 | 返回 `v_pv_none_match` | 必须带 sh/sz/hk |
| GBK 编码不处理 | 中文乱码 | `.decode('gbk')` |
| 周末/节假日拉行情 | 返回上一交易日数据 | 注意交易时间 |

## 八、输出规范

1. **数据有时间戳** — 每个数据点标注拉取时间
2. **多源冲突标注** — 不一致时说明原因
3. **反向搜索必出** — 不能只有利好
4. **实时数据优先** — API > OCR > 人工 > 记忆
5. **不下结论** — 只呈现数据，判断交给用户
